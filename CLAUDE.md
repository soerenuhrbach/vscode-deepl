# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A VS Code extension ("Translate with DeepL") that translates selected editor text via the DeepL API. Published to the marketplace as `soerenuhrbach.vscode-deepl`.

## Commands

Package manager is **yarn** (see `yarn.lock` / `.yarnrc`).

```bash
yarn install       # install dependencies (also runs `husky install` via postinstall)
yarn watch          # webpack --watch, incremental dev build to dist/extension.js
yarn build          # one-off dev build (webpack)
yarn package        # production build with hidden source maps (used by vscode:prepublish)
yarn lint           # eslint src --ext ts
yarn lint:fix       # eslint --fix
```

There is no automated test suite (no `test` script, no test files under `src`). `.vscode/launch.json` and `tasks.json` still reference an `Extension Tests` config and `out/test/suite/index`, but that scaffold is unused — do not assume tests exist or try to run them.

To manually try a change: open the repo in VS Code and press F5 (the "Run Extension" launch config runs the default build task — `yarn watch` — then opens an Extension Development Host window with the extension loaded).

`husky`'s pre-commit hook runs `lint-staged` (eslint --fix on staged `*.ts`) and then `yarn build`.

## Architecture

The extension bundles from a single entry point, `src/extension.ts`, via webpack (`webpack.config.js`) into `dist/extension.js` (commonjs2, `vscode` left external). `activate()` there wires together three things: extension state setup, the status bar item, and command registration. Commands, their titles, keybindings, and context-menu entries are declared in `package.json` under `contributes`; the string constants for command IDs and config keys live in [src/constants.ts](src/constants.ts) and are shared by both `package.json`-adjacent code and the TS sources.

### Reactive state (`src/state.ts`)

State management is the one non-obvious piece of architecture: it uses `@vue/reactivity` (`reactive`/`effect`) as a small reactive store, not a VS Code-specific pattern. `state` (typed by `ExtensionState` in [src/types.ts](src/types.ts)) is a single reactive object merging three different persistence layers:

- **Secret Store** (`context.secrets`) — the DeepL API key only. It used to live in plain config; `migrateApiKeyFromConfigToSecrets` moves it out on startup for any pre-existing installs.
- **Workspace state** (`context.workspaceState`) — the currently selected source/target language (per-workspace, changes often).
- **User/global settings** (`vscode.workspace.getConfiguration()`) — everything else (formality, tag handling, glossary id, translation mode, etc.).

`setup()` loads all three into `state` once, then registers an `effect()` per field that writes back out to the owning store whenever that field changes — so any code can just mutate `state.targetLanguage = ...` and the right persistence layer (secrets vs. workspaceState vs. config) updates automatically. It also listens for external changes (`secrets.onDidChange`, `workspace.onDidChangeConfiguration`) and reloads `state` from disk when they fire, so state stays in sync if the user edits settings.json directly. The status bar ([src/status-bar.ts](src/status-bar.ts)) is itself just another `effect()` reading from `state`.

### Translation flow

- [src/deepl.ts](src/deepl.ts) wraps `deepl-node`'s `Translator`, lazily creating one per call from `state.apiKey` and the current settings in `state`. It caches the source/target language lists (`cache.targetLanguages` / `cache.sourceLanguages`) for the life of the extension host.
- Failure handling is interactive rather than thrown-and-logged: an `AuthorizationError` triggers a modal prompting the user to re-enter their API key and retries once; a translation that comes back identical to the input (a common DeepL symptom of a wrong source/target language) triggers a modal offering to reselect source or target language and retry. Both paths recurse into `translate(...)` with a decremented `retries` counter.
- [src/commands.ts](src/commands.ts) contains the actual command implementations (`translate`, `translateTo`, `translateToFrom`, `duplicateAndTranslate`, `translateAndPasteFromClipboard`). The plain `translate`/`translateTo`/`translateToFrom` commands are all generated by one factory, `createTranslateSelectionsCommand`, parameterized by whether to force the source/target language picker. All commands respect `state.translationMode` (`Replace` / `InsertLineBelow` / `InsertLineAbove`) when applying the edit.
- [src/prompts.ts](src/prompts.ts) holds the QuickPick/InputBox prompts (API key, source language, target language) shared across `commands.ts` and `deepl.ts`.

### Adding a new setting

A new `deepl.*` setting typically touches four places: the JSON schema in `package.json` (`contributes.configuration`), a `CONFIG_*` key in [src/constants.ts](src/constants.ts), a field on `ExtensionState` in [src/types.ts](src/types.ts), and load/persist wiring (`loadExtensionState` + a corresponding `effect()`) in [src/state.ts](src/state.ts).
